# 実対話テストデータの作り方（人手アノテーション版）

実際のロールプレイ相談音声から、**User 側の発話をテスト入力として切り出す**。
正解は人が付けたアノテーション TSV であり、スクリプトはそれを WAV に切り出す
だけ。ダイアライゼーションも ASR も使わない。

**TSV が正、WAV はその出力**という関係にしてある。TSV を直してもう一度実行
すれば作り直される。

## アノテーション TSV

音声と同じ名前で拡張子だけ `.tsv` にしたものを、音声の隣に置く。

```
/path/dialogue1.wav
/path/dialogue1.tsv
```

| 列 | 内容 |
|---|---|
| `Speaker` | `Staff` または `User` |
| `Transcription` | 人手の書き起こし |
| `Start` | 発話開始。`00:00:15.500` 形式 |
| `End` | 発話終了。同上 |

```
Speaker	Transcription	Start	End
User	もしもし、あの、相談したいことがありまして	00:00:15.500	00:00:21.200
Staff	はい、お伺いします	00:00:21.000	00:00:23.000
```

ヘッダ行はあってもなくてもよい。無ければ上の順に並んでいるものとして読む。
列名は `話者` / `書き起こし` / `開始` / `終了` などの表記ゆれも受ける。

時刻は `HH:MM:SS.mmm` のほか `MM:SS.mmm` / `SS.mmm` も受け、小数点はピリオド
でもカンマでもよい（Excel やツールによって変わるため）。

## Audacity のラベルから作る

Audacity でラベル付けした場合は、書き出したラベルをアノテーション TSV へ変換する。
入力は `File > Export > Export Labels` が吐く形式。

```
15.500000	21.200000	User: もしもし、あの、相談したいことがありまして
21.000000	21.600000	Staff: はい
```

```bash
uv run python scripts/labels_to_annotation_tsv.py /path/labels/
```

出力は入力と同じ名前で拡張子を `.tsv` にしたもの。`--out-dir` に音声のフォルダを
渡せばそこへ直接出せる。**TSV は音声と同じ名前で音声の隣に置く**必要がある。

話者はラベル文字列の**最初のコロンまで**（全角コロンも可）。書き起こしに
`10:30` のようなコロンが入っていても、最初の 1 つでしか切らないので影響しない。
認める話者は既定で `Staff` と `User`。それ以外が出たら綴り間違いを疑って止まる
（意図したものなら `--speakers` で足す）。

次の行は**1 つも書き出す前に**行番号付きで全部挙げてから止まる。

- 列が 3 つ未満
- 時刻が読めない
- 終了 <= 開始（点ラベルを含む。区間にすること）
- 話者が無い / 知らない話者
- 書き起こしが空

スペクトル選択付きで書き出したときに挟まる `\ 低域 高域` の行は読み飛ばす。
既存の `.tsv` は `--overwrite` を付けない限り上書きしない。

変換の最後に、話者ごとの件数・発話の合計秒・**異話者どうしの重なりの組数**が出る。
1ch 対話では重なりは正常なので、件数の確認だけに使う。

## 実行

音声フォルダを渡すと、中の WAV を全部処理する。

```bash
uv run python scripts/build_test_wav_from_tsv.py /path/dialogues/
```

出力先の既定は **`data/test_data/real_dialogue`**（本番用テストデータの置き場）。
テストデータは固定で使うものなので、既定を決め打ちにして毎回同じ場所へ出す。
別の場所に出したいときだけ `--out-dir` を付ける。

WAV を個別に指定してもよい。フォルダと個別指定を混ぜても、同じ WAV が二重に
処理されることはない。

```bash
uv run python scripts/build_test_wav_from_tsv.py /path/d1.wav /path/d2.wav
```

GPU も NeMo も Whisper も要らない（numpy と soundfile だけ）。ジョブ投入も不要。

```
data/test_data/real_dialogue/
├── manifest.json            全対話の内訳と合計
├── dialogue1/
│   ├── User/0000_00m15.5s_5.7s_ov_もしもしあの相談したいことがあり.wav
│   ├── clips.tsv            採用したもの一覧
│   └── dropped.tsv          落としたもの一覧（理由付き）
└── dialogue2/
    └── ...
```

`manifest.json` には対話ごとの件数・秒数・重畳件数と、適用したフィルタ条件、
生成時刻が入る。テストデータが変わっていないことの確認に使える。

実行の最後に一覧が出る。

```
=== テストデータ ===
data/test_data/real_dialogue
  dialogue1                  47 件   312.4 秒  (除外 23, 重畳 5)
  dialogue2                  38 件   256.1 秒  (除外 19, 重畳 3)
  合計                       85 件   568.5 秒  (除外 42, 重畳 8)
```

## 相槌の除去

「はい」のような相槌も 1 発話として書かれているので、既定では**記号を除いた
文字数が 5 未満の発話を落とす**（`--min-chars 5`）。

落としたものは `dropped.tsv` に理由付きで残るので、閾値が妥当だったか後から
確認できる。5 が厳しすぎ／緩すぎと分かったら値を変えて再実行する。

長音「ー」は文字数に数える。記号ではなく実文字で、除くと「えーっと」が 3 文字
になり、相槌でない発話まで落ちてしまう。

`--min-sec` で長さによる足切りもできる（既定 0 = 無効）。

## 重畳区間

1ch 録音なので、User の発話が Staff の発話と重なっている区間では**相手の声が
同じ標本に混ざっており、消せない**。

該当するクリップはファイル名に `_ov` が付き、`clips.tsv` の `overlap_sec` 列に
秒数が出る。ジョブの最後にも件数を警告として出す。相手の声が混ざって困るものは
そこを見て外すこと。

`--mute-other` を付けると、切り出した区間のうち**相手だけが喋っている部分**を
無音化する。重畳部そのものは消せないので、これは補助でしかない。

## 主なオプション

| オプション | 既定 | 意味 |
|---|---|---|
| `--out-dir` | `data/test_data/real_dialogue` | 出力先ルート |
| `--recursive` | off | フォルダを再帰的に探す |
| `--speaker` | `User` | 切り出す話者ラベル。大文字小文字は区別しない |
| `--min-chars` | `5` | 記号を除いた文字数がこれ未満なら落とす。0 で無効 |
| `--min-sec` | `0.0` | これより短い発話を落とす。0 で無効 |
| `--mute-other` | off | 相手だけが喋っている部分を無音化 |
| `--annotation` | WAV と同名 `.tsv` | TSV を明示指定（WAV 1 つのときのみ） |

出力ディレクトリ名は `--speaker` の綴りではなく **TSV 上の実ラベル**を使う。
`--speaker staff` と `--speaker Staff` で別フォルダができると混乱するため。

## 停止する条件

黙って通すと結果が静かに壊れるものは、**WAV を 1 つも書く前に**行番号付きで
報告して停止する。

- `End <= Start` の行
- 時刻の形式が不正な行
- 列数が足りない行
- 指定した話者ラベルの発話が 1 件も無い（TSV にあるラベル一覧を出す）
- 対応するアノテーション TSV が無い WAV がある

最後のものは、**1 件でも欠けていれば何も書く前に**欠けているものを全部挙げて
止まる。1 件ずつ処理しながら落ちると、テストデータが中途半端に出来た状態で
止まってしまうため。

TSV の最終時刻が音声長を超えている場合は、音声と TSV の組み合わせ違いを疑って
警告を出す（停止はしない）。

## タイムスタンプが音声と合っていないとき

書き起こし・話者ラベル・発話の**順番**が正しく、時刻だけが合っていない場合は、
時刻を音声から復元できる。`scripts/realign_annotation_tsv.py` がそれをやる。

```bash
qsub -v WAVS=/path/dialogues scripts/run_realign_annotation.pbs
```

やっていることは 3 段。

1. **概算** — faster-whisper で全体を書き起こし（単語タイムスタンプ付き）、
   人手 TSV と ASR の**読み**（pyopenjtalk で katakana 化）を照合する。一意な
   6-gram 一致を anchor にし、最長増加部分列で単調な対応だけを残す。照合は
   **話者ごと**に行う。重畳があっても同一話者内の発話順は必ず単調だから。
2. **実測** — 概算位置の前後 ±2 秒だけを切り出し、その発話のテキストだけで
   MMS_FA の CTC 強制アライメントを掛けて `start` / `end` を出す。
3. **吸着** — silero VAD の音声区間端へ ±0.4 秒以内でスナップする。

応答レイテンシは「User の `end` → Staff の `start`」で測る。評価の精度はそのまま
境界の精度なので、2 と 3 はそのための追い込み。

読みを介して照合するのがこの処理の要。ASR が「こんにちは」と書き、人手 TSV が
「今日は」と書いていても、どちらも `コンニチワ` になるので anchor が張れる。

**元の TSV は書き換えない。** 出力は `data/test_data/realign/<stem>/` に出る。

| ファイル | 内容 |
|---|---|
| `labels/` | Audacity 用ラベル（下記） |
| `aligned.tsv` | 合わせ直した TSV。そのままアノテーション TSV として使える形式 |
| `report.tsv` | 1 行ごとの新旧時刻・ずれ・`coverage`・手法・`flags` |
| `summary.json` | ずれの統計と診断 |
| `asr.json` | ASR の単語タイムスタンプ（再実行時のキャッシュ） |
| `review_wav/` | 新しい境界で切った確認用 WAV（前後 0.5 秒の余白付き） |

### Audacity で確認する

元の WAV を Audacity で開き、**File > Import > Labels** で `labels/` の中を読む。
1 ファイルが 1 ラベルトラックになるので、複数読めば並べて見比べられる。

| ファイル | 中身 |
|---|---|
| `all.txt` | 合わせ直した全発話 |
| `<話者>.txt` | 話者ごと（`User.txt` / `Staff.txt`）。重畳を目で見るならこれ |
| `flagged.txt` | 要確認の行だけ。ここから見るのが早い |
| `original.txt` | **元の TSV の時刻**。`all.txt` と並べればずれ方が一目で分かる |

形式は Audacity 標準の `開始秒<TAB>終了秒<TAB>ラベル`。ラベルは
`User: もしもし、あの…`、要確認の行は `User[LOWCOV/DUR]: …` のように出る。
BOM 無し UTF-8、改行 LF。

境界を直したら **File > Export > Export Labels** で書き出せる。同じ 3 列形式なので、
話者と書き起こしはラベル文字列から戻せる。

### flags の意味

`report.tsv` と `flagged.txt` に出る印。

| flag | 意味 |
|---|---|
| `LOWCOV` | anchor がほとんど張れていない。周辺の補間に頼っている |
| `NOFA` | 強制アライメントが失敗し、概算のままになっている |
| `DUR` | 文字数から見て長さが極端。境界が外れている疑い |
| `CROSS` | 同一話者の隣の発話と重なったので均した |
| `NOTEXT` | 照合できる読みが取れず、元の時刻のままにした |

### 先にずれの性質を見る

`--check-only`（`EXTRA_ARGS="--check-only"`）を付けると ASR と概算までで止まり、
`report.tsv` とラベルと診断だけを出す。診断は 3 種類。

- `constant_offset` — 全体が一定量ずれている。録音の頭切れや、別ファイルの TSV を
  流用した可能性。**原因を直したほうが確実**なので、まずそちらを疑う。
- `linear_drift` — 時間に比例してずれが増える。サンプリングレートの取り違え。
  これも倍率が出るので、元を直せる。
- `irregular` — 行ごとにばらついている。行単位で付け直すしかない（本処理の出番）。

### 順番について

`read_annotation` は `start` でソートして返す。時刻が信用できない状態でこれを
使うと**正しい並び順が壊れる**ので、再アライメント側は行番号（＝TSV の並び順）で
並べ直してから処理する。
