# 相談背景とは独立した5つの対話軸

更新日：2026-10-14。軸の版：`interaction_axes_v1`。

400種類の背景とは別に、今日どう話したいか、何が支援利用を難しくしているか、やり取りにどう反応するかを選びます。人物の性格と、その日の話し方は別の設定です。

| 軸 | 候補 |
|---|---|
| 今日の相談目的 | 聴いてほしい／状況を整理したい／支援を知りたい／何を相談したいか分からない |
| 支援への障壁 | 過去に断られた／迷惑をかけたくない／費用／移動／電話が苦手／個人情報への不安 |
| 話し方 | 一言だけ／遠回し／長い説明／冗談でごまかす／怒り／話題が行き来する |
| 開示の仕方 | 最初から話す／少しずつ話す／一部は話さない／途中で訂正する |
| 対話への反応 | 質問に答える／答えにくいと言う／提案を断る／誤解を指摘する／終了を望む |

好奇心の背景には「窓口や対話を試したい」、日常や嬉しい報告には「出来事や嬉しさを共有したい」も用意し、悩みの相談へ無理に変えません。

## 組み合わせ方

- 各ケースに `interaction_axes` を保存します。同じ背景でも各軸の組み合わせは変わります。すべての組み合わせを生成する方式ではなく、乱数シードで再現できる抽選です。
- 悩みの背景では目的4種類から抽選します。好奇心・日常・嬉しい報告では背景に合う目的を選びます。
- 障壁は0〜2個。0個・1個・2個の抽選重みは50・35・15です。嬉しい報告には障壁を必須にせず、現在は0個にします。この配分はデータ生成の設定であり、実際の相談者の比率を表す統計ではありません。
- 話し方と開示はそれぞれ選びます。嬉しい報告には無関係な怒りを足しません。
- 「一言だけ」は各発話の文数の指示より優先し、長い説明では4〜6文を指示します。怒りを選んだ場合は音声向けの感情ラベルも「気持ちが高ぶる」にします。
- 「最初から話す」に、従来の「少しずつ開示する」を重ねません。「一部は話さない」では、聞かれたことにすべて答えるよう強制しません。「途中で訂正する」は実際の自分の前の発話がある時だけ促します。
- 障壁を毎回列挙させず、該当する場面ににじませます。費用・制度・個人情報の扱いを架空の事実で補いません。

## 現在の相槌条件での扱い

`ongoing` 条件では、相談目的・障壁・話し方・開示を生成指示へ反映します。例えば「支援を知りたいが費用と個人情報が不安な人が、遠回しに一部の事情だけ話す」という組み合わせを作れます。

相槌だけの聞き手は制度の説明や提案を返しません。そのため、支援を知りたい理由や障壁は話せますが、紹介された支援を選ぶやり取りの教師データにはなりません。

質問への回答・答えにくさ・提案の辞退・誤解の指摘は、前提となる質問・提案・受け止めが実際の会話履歴にある場合だけ促します。相槌しかなかったのに「その提案は断ります」と言わせることはしません。誤解の指摘も、実際に意味がずれている場合だけという指示で、故意に誤解を作らせるものではありません。

`interaction_axes.reaction` は条件付きの生成目標です。実際にその反応が現れたことを示す正解ラベルではありません。軸の抽選・プロンプトへの反映と、生成された発話の実現率は分けて評価してください。

## 終了希望は別条件

`end-request` 条件だけが「終了を望む」を持ちます。現在の継続相槌の比較実験には混ぜません。終了条件を相槌専用生成へ渡すと、LLMを呼ぶ前に拒否します。

この条件は応答ありの `multi-agent` で生成します。原則1往復後に本人から明確に終了を申し出る指示を出し、終了希望がなければ1回書き直しを求めます。標準の失敗方針では、なお明確な終了希望が出なければその対話を失敗とします。本人の直接の終了希望を検出したら、聞き手は短く了承し、最低往復数を満たすために引き留めません。終了希望の検出は明示的な表現に限定したルールであり、あらゆる遠回しな終話を理解する仕組みではありません。

ケースだけ確認する場合（GPU・LLMは使いません）：

```bash
python scripts/build_full_duplex_training_use_cases.py \
  --out-path data/use_cases/end_request_100.jsonl \
  --num 100 --seed 0 --listening-ratio 1 --interaction-track end-request
```

対話を生成する場合（既存のQwen実行環境があるサーバー）：

```bash
NUM_CASES=100 qsub -V scripts/2026-10-14/prepare_end_request_dialogues.pbs
```

出力先の既定は `data/runs/qwen_end_request_100_axes_v1/` です。`END_REQUEST_ID` と `END_REQUEST_ROOT` で変更できます。この変更ではジョブ投入・GPUによる生成は実施していません。

## 保存・再開

ケースと対話の両方に `interaction_axes` を保存し、再読込でも保持します。現在の相槌生成は `listener_protocol.interaction_axes_version` を検査し、この軸を導入する前の生成済み対話への継ぎ足しを拒否します。比較実験の既定IDも `aizuchi_compare_2026-10-14_backgrounds_v2_axes_v1_<件数>` に分けました。

生成指示、条件の分離、実際の終了希望後の停止は自動テストで確認できます。LLMの自然さ、各反応の出現率、支援利用の障壁が自然に表現されるかは、小規模生成による内容確認が必要です。
